# Checklist de qualidade de README

Use estes itens para auditar um README antes de reescrever. Marque o que falta ou está fraco.

## Estrutura essencial

- [ ] Título curto e o nome do projeto já diz do que se trata (ou tem uma frase logo abaixo que diz)
- [ ] Uma frase de valor logo no topo: o que o projeto faz e para quem serve
- [ ] Seção de instalação com os comandos reais (testados, não genéricos como "instale as dependências")
- [ ] Exemplo de uso com código ou passo a passo real — idealmente um antes/depois ou input/output
- [ ] Licença indicada (arquivo LICENSE + menção no README)

## Sinais de README fraco

- Título genérico tipo "Meu Projeto" ou nome sem contexto do que faz
- Primeiro parágrafo técnico demais, sem dizer o problema que resolve
- Instruções de instalação incompletas ou desatualizadas
- Sem nenhum exemplo visual ou de código — só texto corrido
- Seções vazias ou com "TODO" esquecido

## Sinais de README forte

- Consegue-se entender o que o projeto faz em 10 segundos de leitura
- Tem pelo menos um exemplo concreto (código, screenshot descrito, ou trecho de saída real)
- Instalação testável do zero, sem pressupor conhecimento prévio do autor
- Badges relevantes (build passando, versão, licença) quando fazem sentido pro projeto
- Tom consistente do início ao fim
